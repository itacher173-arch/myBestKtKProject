# База знаний КТК ЭЛОУ-АВТ

Модуль хранит учебные статьи отдельно от программного кода и собирает единый каталог при запуске. Источником истины для нового контента являются JSON-пакеты в `content/ru`; `seed.json` оставлен как совместимый базовый набор для старых ссылок.

## Рекомендуемая структура

```text
backend/knowledge/
├── content/ru/              # пакеты статей по предметным областям
├── assets/                  # обезличенные SVG-схемы
├── schema/article.schema.json
├── catalog.py               # загрузка, нормализация, индексирование
├── seed.json                # совместимый базовый набор идентификаторов
└── app.py                   # HTTP API, поиск и раздача схем
```

## Жизненный цикл статьи

1. Автор создаёт или изменяет статью в отдельной ветке.
2. Автоматические тесты проверяют идентификаторы, связи, источники и обязательное предупреждение.
3. Технолог проверяет физическую корректность и отсутствие универсальных «реальных» уставок.
4. Специалист по промышленной безопасности проверяет опасные операции.
5. Владелец обучения переводит статус в `approved-for-training` и указывает ревизию.
6. Изменение реального регламента запускает MOC для связанных статей, сценариев и математической модели.

## Правила публикации

- Не коммитить внутренние регламенты, P&ID, реальные теги, уставки, учётные данные и персональные данные.
- Публичные ссылки вести на первичные источники: регулятор, орган расследования, стандарт или изготовитель.
- Не копировать значительные фрагменты защищённого текста; писать самостоятельное учебное изложение.
- Любая инструкция по потенциально опасному действию содержит границу применимости и ссылку на локальный регламент.
- Сохранять прежний `id`, если на статью ссылаются ИИ, мини-тренировки или оборудование.
- Для каждой статьи задавать `relatedArticleIds`, `equipmentIds` и `scenarioIds`, где это применимо.

## Рекомендуемый GitHub-процесс

- `CODEOWNERS`: технолог, промышленная безопасность, методолог и владелец приложения.
- Pull request template с чек-листами факт-проверки, ИБ, авторских прав и обратной совместимости.
- Защита `main`, обязательные тесты и минимум два одобрения для статей безопасности.
- Автоматическая проверка JSON Schema, битых ссылок, дубликатов `id` и несуществующих связей.
- Выпуск версий контента отдельными тегами (`knowledge-vX.Y`) и журнал изменений.

Материалы предназначены только для КТК и не заменяют документацию конкретного производственного объекта.
