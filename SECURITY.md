# Политика безопасности

## Область поддержки

Текущий репозиторий содержит учебный прототип. Поддерживается только актуальное состояние ветки `main`; исторические демонстрационные версии не получают security-исправления.

## Сообщение об уязвимости

Не создавайте публичный issue с подробностями уязвимости, токенами, дампами, персональными или производственными данными. Используйте GitHub Private Vulnerability Reporting, если функция включена для репозитория, либо свяжитесь с владельцем репозитория через закрытый корпоративный канал.

В сообщении укажите:

- компонент и commit SHA;
- условия воспроизведения и влияние;
- минимальный безопасный proof of concept;
- затронутые роли и данные;
- предложенное исправление, если оно известно.

Владелец подтверждает получение, определяет критичность и согласует срок раскрытия после выпуска исправления.

## Данные, запрещённые к публикации

- `.env`, пароли, cookie, Bearer-токены, private keys и доступы к registry;
- реальные P&ID, теги, уставки, адреса и конфигурации промышленного контура;
- внутренние регламенты без разрешения владельца;
- персональные данные и необезличенные учебные журналы;
- полные тексты материалов, лицензия которых не разрешает распространение;
- неутверждённые production endpoints и сведения, упрощающие обход защиты.

Перед публикацией используйте чек-лист из pull request template и secret scanning.

## Текущие ограничения прототипа

- локальная авторизация ещё не заменена корпоративным OIDC/AD;
- совместимый клиентский fallback сохраняет токен в `sessionStorage`;
- Compose использует одиночные экземпляры БД и кэша;
- TLS, WAF, Vault, SIEM и централизованный audit transport отсутствуют;
- Docker-образы и зависимости требуют корпоративного сканирования и подписи;
- минимальная длина локального пароля прототипа не соответствует production-политике.

Поэтому текущий стек нельзя размещать в production или публиковать в интернет без отдельного security hardening.

## Минимальные требования перед корпоративным внедрением

- OIDC Authorization Code + PKCE/BFF и корпоративная MFA-политика;
- HttpOnly/Secure/SameSite cookies без токена, доступного JavaScript;
- WAF, TLS, сетевые политики и запрет публичных внутренних портов;
- Vault/secret operator и регулярная ротация;
- SAST, SCA, secret scan, container scan, SBOM и подпись артефактов;
- PostgreSQL HA/PITR и проверенный restore;
- неизменяемый централизованный аудит и интеграция с SIEM;
- threat model, pentest и устранение критических/высоких замечаний;
- отдельные TEST, PREPROD и PROD с минимальными правами;
- изолированный AI-контур, фильтрация контекста и eval/red-team gates.

## Зависимости

Dependabot отслеживает Python, npm, Docker и GitHub Actions. Обновление зависимости принимается после CI, проверки лицензии, changelog и влияния на локальный/offline режим.
