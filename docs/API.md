# Публичный API прототипа

Основная точка входа — gateway `http://localhost:8000/api`. В браузерном сценарии запросы проксируются Nginx с того же origin. Защищённые маршруты используют cookie `ktk_session`; Bearer-токен сохранён для совместимости прототипа.

## Системные маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | агрегированное состояние сервисов |
| `GET` | `/api/live` | процесс доступен |
| `GET` | `/api/ready` | зависимости готовы |
| `GET` | `/api/metrics` | технические метрики; инструктор/администратор |

## Авторизация и пользователи

| Метод | Маршрут | Доступ |
| --- | --- | --- |
| `POST` | `/api/auth/login` | публичный вход |
| `POST` | `/api/auth/logout` | пользователь |
| `GET` | `/api/auth/me` | пользователь |
| `GET` | `/api/users` | администратор; список обучаемых также инструктор |
| `POST`, `PATCH`, `DELETE` | `/api/users/*` | администратор |

Саморегистрация отключена. Допустимые роли: `trainee`, `instructor`, `admin`; пользователь может иметь несколько ролей.

## Симуляция

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/api/sim/sessions` | создать серверную сессию |
| `GET` | `/api/sim/sessions/{session_id}` | получить проекцию состояния |
| `POST` | `/api/sim/sessions/{session_id}/command` | применить разрешённую команду |
| `WS` | `/api/sim/ws/{session_id}` | поток состояния и событий |
| `POST` | `/api/scenarios/validate` | проверить структуру сценария; инструктор/администратор |

Создание сессии фиксирует seed и версии модели/сценария. Команда должна содержать ожидаемую версию состояния; конфликт версий не должен молча перезаписывать более новое состояние.

## Отчёты, группы и аудит

| Маршрут | Назначение |
| --- | --- |
| `/api/reports*` | отчёты с фильтрацией по владельцу и роли |
| `/api/groups*` | группы, инструктор и участники |
| `/api/audit*` | журнал и проверка HMAC-цепочки |

Обучаемый видит только собственные результаты. Инструктор работает со своими группами; администратор управляет всеми пользователями и группами.

## AI

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/api/ai/analyze` | разбор завершённой сессии |
| `POST` | `/api/ai/risk-preview` | предварительная оценка рисков |
| `POST` | `/api/ai/chat` | ответ по текущему контексту и базе знаний |

Ответ должен отражать фактически использованный режим: ML/RAG/LLM либо fallback, а также версии модели, индекса и prompt-контракта. AI-ответ не является командой симулятору или обязательной оценкой.

## Правила эволюции API

- несовместимые изменения требуют новой версии маршрута или периода совместимости;
- схемы запросов и ответов должны быть перенесены в версионируемую OpenAPI-спецификацию до PREPROD;
- ошибки возвращаются в JSON с полем `error` и корректным HTTP-статусом;
- новые защищённые маршруты сопровождаются тестами `401`, `403` и разрешённой роли;
- персональные и производственно-чувствительные данные не передаются в AI-контур.
