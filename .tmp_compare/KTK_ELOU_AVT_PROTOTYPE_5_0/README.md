# КТК ЭЛОУ-АВТ 5.0 — итоговый локальный прототип

Модульный компьютерный тренажёр установки ЭЛОУ-АВТ: динамическая технологическая модель, интерактивная мнемосхема, 13 сегментных мини-тренировок, сценарии SC-01…SC-15, автономная база знаний, ролевая авторизация и локальный объяснимый ИИ-модуль.

Прототип не подключается к реальной АСУ ТП и предназначен только для обучения.

## Возможности версии 5.0

- современное окно авторизации и три демонстрационные роли: обучаемый, инструктор, администратор;
- единая оболочка приложения с навигацией, состоянием сервисов и меню пользователя;
- новый учебный дашборд, поиск и фильтрация мини-тренировок, карточка запуска и персональный маршрут;
- настройки светлой, тёмной и системной темы, языка оболочки, семейства и масштаба шрифта, плотности, контраста и анимации;
- отключаемый ИИ в интерфейсе и на уровне серверной конфигурации;
- ИИ-разбор полной истории действий, событий, результата и финального состояния процесса;
- выявление критических отклонений, повторных команд, превышения времени реакции и проблем качества;
- рекомендации конкретных мини-тренировок и прямые ссылки на соответствующие статьи базы знаний;
- ИИ-чат во всех разделах, использующий текущий контекст симуляции и локальную базу знаний;
- обновлённое рабочее место инструктора: сводка, журналы, события и сохранённый ИИ-разбор;
- автономная работа без внешних API, CDN и облачных моделей.

## Запуск на чистом Windows-ПК

1. Распакуйте архив, например в `C:\KTK-ELOU-AVT-5.0`.
2. Запустите `INSTALL_ALL_WINDOWS.cmd` от обычного пользователя.
3. Установщик проверит Python 3.12 и Node.js LTS, при необходимости загрузит их через `winget`, создаст `.venv`, выполнит `npm.cmd ci`, соберёт frontend и запустит тесты.
4. Запустите `START_ALL_WINDOWS.cmd`.
5. Откроется `http://127.0.0.1:8000`.

Для остановки используйте `STOP_ALL_WINDOWS.cmd`. Повторная установка зависимостей выполняется через `REINSTALL_DEPENDENCIES_WINDOWS.cmd`.

Установщик вызывает `npm.cmd`, поэтому системный запрет выполнения `npm.ps1` не препятствует установке.

| Роль | Логин | Пароль |
| --- | --- | --- |
| Обучаемый | `trainee` | `Ktk2026!` |
| Инструктор | `instructor` | `Instructor2026!` |
| Администратор | `admin` | `Admin2026!` |

Учётные записи предназначены для локального прототипа. Перед общим развёртыванием замените секрет подписи и подключите корпоративный IdP.

## Ручной запуск для разработки

В отдельных терминалах из корня проекта:

```text
.venv\Scripts\python.exe -m services.simulator.app
.venv\Scripts\python.exe -m services.scenarios.app
.venv\Scripts\python.exe -m services.training.app
.venv\Scripts\python.exe -m services.knowledge.app
.venv\Scripts\python.exe -m services.auth.app
.venv\Scripts\python.exe -m services.ai.app
.venv\Scripts\python.exe -m services.gateway.app
```

Frontend для разработки:

```text
cd apps\frontend
npm.cmd run dev
```

Vite доступен на `http://127.0.0.1:5173`, собранное приложение — на `http://127.0.0.1:8000`.

## Режимы ИИ

По умолчанию `KTK_AI_PROVIDER=rules`: анализ выполняется объяснимыми локальными правилами, а чат извлекает материалы из корпоративной базы знаний. Внешние запросы отсутствуют.

Опционально администратор может установить локальную Ollama и выбрать `KTK_AI_PROVIDER=auto` или `ollama`. Адрес и модель задаются через `KTK_OLLAMA_URL` и `KTK_OLLAMA_MODEL`. Если локальная модель недоступна, чат автоматически использует автономный режим базы знаний.

## Наполнение

- мини-тренировки: `services/training/catalog.json`;
- сценарии: `services/scenarios/catalog.json`;
- материалы базы знаний: `services/knowledge/seed.json`;
- демонстрационные пользователи: `services/auth/users.json`;
- переменные среды: `config/.env.example`.

Учебные значения и рекомендации не заменяют производственный регламент конкретной установки.
