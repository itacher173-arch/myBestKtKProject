# Архитектура КТК ЭЛОУ-АВТ 5.0

Проект организован как monorepo. Пользователь работает только с API Gateway; внутренние Python-службы запускаются и масштабируются независимо.

## Компоненты

| Компонент | Технология | Ответственность |
| --- | --- | --- |
| `apps/frontend` | React 18, TypeScript, Vite, SVG | Авторизация, оболочка, настройки, мнемосхема, тренировки, отчёты, база знаний и ИИ-интерфейс |
| `services/gateway` | Python HTTP | Единая точка входа, проверка Bearer-токена, маршрутизация API, публикация production frontend |
| `services/auth` | Python, PBKDF2, HMAC-SHA256 | Локальная ролевая авторизация, подписанные сессии и проверка токенов |
| `services/simulator` | Python | Динамическая модель ЭЛОУ-АВТ, команды, инженерные среды, аварии, сигналы и журнал |
| `services/scenarios` | Python, JSON | Каталог сценариев и независимая оценка результата |
| `services/training` | Python, JSON | Декларативные мини-тренировки, разрешённые действия, цели и подсказки |
| `services/knowledge` | Python, SQLite | Статьи, категории, полнотекстовый поиск и источники |
| `services/ai` | Python, rule engine, локальный RAG | Анализ траектории действий, интерпретация результата, рекомендации и чат |
| `services/common` | Python | Общая HTTP/JSON-инфраструктура, CORS и обработка ошибок |

## Поток запроса

1. Пользователь входит через `/api/auth/login`.
2. Frontend хранит подписанный токен только в `sessionStorage` и передаёт `Authorization: Bearer`.
3. Gateway проверяет токен через Auth перед каждым защищённым запросом.
4. Simulator ведёт состояние процесса и подробный журнал действий.
5. При завершении сессии frontend сохраняет локальный отчёт и отправляет снимок процесса и журнал в AI service.
6. AI service возвращает объяснимые выводы, ссылки на статьи и идентификаторы мини-тренировок.
7. Чат получает только текущий учебный контекст и извлечённые материалы базы знаний.

## Модульность frontend

- `src/auth` — сессия и окно входа;
- `src/layout` — оболочка и навигация;
- `src/settings` — предпочтения и доступность;
- `src/ai` — типы, чат и отчёт ИИ;
- `src/knowledge` — база знаний;
- `src/miniTraining` — каталог, критерии и панель урока;
- `src/sim` — состояние, API-адаптер, модель интерфейса и отчёты;
- `src/scheme` и `src/components/scheme` — топология и SVG-мнемосхема;
- `src/components` — пользовательские панели и рабочие экраны;
- `src/lib` и `src/ui` — общий API-клиент и визуальные примитивы.

Каталоги уроков и материалов декларативны. Добавление учебного сегмента не требует изменения механизма авторизации, шлюза или ИИ-интерфейса.

## Граница прототипа и промышленного решения

Локальные HMAC-токены и `localStorage` применены для автономного прототипа. В корпоративном развёртывании интерфейс API сохраняется, а реализации заменяются на OIDC/AD, PostgreSQL HA, Redis, S3, очередь сообщений и централизованный аудит. AI service допускает полное отключение и не зависит от Simulator.
